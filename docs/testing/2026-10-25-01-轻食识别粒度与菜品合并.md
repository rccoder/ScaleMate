# 轻食识别粒度与菜品合并

> 2026-10-25。用户指出食物库对轻食等组合菜拆分过细，同意修正规则并增加核对合并入口。实现基于 `0.3.2` 后工作区，尚未提交或公开发版。

## 问题与实现

原 Prompt 只要求合并同一道菜的重复照片，没有明确成品菜和原材料的边界。模型若把鸡胸肉轻食拆成鸡胸肉、蔬菜、谷物、酱汁，原入库逻辑会逐项收录；这是粒度约束缺失，不是所有菜品识别都失败。

- Prompt 明确以成品菜或独立供应的食物／饮料为单位，重点约束轻食、沙拉、谷物碗、盖饭和汤面。配料、油和酱汁计入整菜一次，写进估算说明，不同时输出整菜和原材料；独立米饭、配菜和饮料分开，不靠同图／同盘盲目合并。
- 照片结果核对页有至少两项时，提供“合并为一道菜”。用户选择至少两项、填写菜名与本人份量，查看营养预览后确认。选中项目在首个选中项位置替换为一个新菜品，其余项目及顺序不变；取消不修改。
- 合并只针对当前未确认批次，不保存餐食、不写健康记录、不调用 AI。合并后仍留在结果页，可继续编辑，最终绿色对号沿用一次确认并保存整餐的流程。
- 相加的是已有的本人实际摄入；编辑形成的倍率先归一化，不再按人数分摊。缺任一营养的对应合计保留未知，克数只有全部已知才相加；不合法数值、溢出或无法形成任何有效营养合计时拒绝合并。
- 保留图片去重、原项目的估算说明和建议、本人摄入解释／警告，批次的整餐建议、耗时和 Token 不变；合并项解除对原单项食物库基准的引用，确认后才按新菜名正常收录。旧条目与星标不自动删除、合并或改写。

代码入口：`FoodDishMerge.kt`、`FoodDishMergeDialog.kt`、`FoodViewModel.mergeDish`、`FoodScreen` 照片结果页、`AiClient` 识别 Prompt。规则同步写入 [饮食 PRD](../11-称伴食物%20AI%20记录产品需求文档.md) 和根 AGENTS。
