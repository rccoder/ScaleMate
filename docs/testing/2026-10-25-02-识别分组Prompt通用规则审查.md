# 识别分组 Prompt 通用规则审查

> 2026-10-25。用户测试后报告西瓜仍被单独拆出，要求 Prompt 通用且符合常理。本轮在上一轮工作区上修订分组规则，没有改写旧餐食或食物库，尚未提交或公开发版。

## 审查结论与改动

上一轮虽然约束了“成品菜不拆配料”，但独立水果和组合餐水果之间的判断仍含糊，也没有明确组成部分的不同食用比例是否要迫使拆项。仅继续列举例外，不能解决记录单位不明确的问题。

本轮保留 JSON、应用语言、本人摄入、多人分食、重试和营养建议合同，将分组整理成先后明确的规则：

1. 先确定人会自然命名和复用的成品菜或组合餐单位，再估算营养。不把每种食材当作一项，也不把整餐、一次套餐购买或整个托盘默认当作一项。
2. 用户明确的组成关系优先，其次是制作、摆放和实际供餐关系，最后才是日常用餐常识。照片、容器或食物类别本身都不是硬边界。
3. 作为一份搭配的组合餐可以分区、没有拌匀，同时有水果、肉蛋、蔬菜和谷物。属于这份组合的内容不因类别或做法不同而拆出；独立供应的菜、配菜或饮料仍分开。
4. 同一组内先分别处理本人摄入、分食、剩余和没吃的成分，再相加一次。不同食用比例不自动改变分组；整菜与配料不能重复计数。
5. 关系确实不明时说明最有证据的分组假设，不虚构套餐、品牌或配方。描述里的菜品事实可以影响分组和份量，不能改变 JSON 合同或目标语言。

仅替换 `AiClient` 中的分组段落，其他输出字段、请求路径、服务配置、Token 统计与确认保存路径沿用现有实现。规则同时写入 [饮食 PRD](../11-称伴食物%20AI%20记录产品需求文档.md) 与根 AGENTS；手动合并仍是纠错入口，不作为模型服从的保证。

## 通用场景检查表

下表是人工规则审查和后续真实 AI 验收的预期，不是已经执行成功的模型评测，也不要求模型使用固定菜名。

| 场景 | 预期分组与摄入处理 |
| --- | --- |
| 搭配好的一份轻食拼盘，西瓜、蔬菜、鸡蛋分区摆放 | 一份轻食，水果属于这份组合，不因分区或水果类别拆项 |
| 水果沙拉或鸡肉谷物碗 | 一份组合，食材和酱汁只计入一次，说明组成与估算假设 |
| 一碗牛肉面 | 一份牛肉面，肉、面、配菜及实际喝下的汤合计 |
| 托盘上独立供应的饭碗、炒菜盘和盒装奶 | 三个独立条目；同托盘不合成一道菜 |
| 轻食旁边另外供应一杯奶／一盒水果 | 轻食和独立加餐分开，不能因为同图就合并 |
| 用户明确水果属于轻食，而包装上有多个隔间 | 尊重明确组合关系，不按包装分区硬拆 |
| 组合餐里谷物只吃一半，水果吃完，酱汁没吃 | 仍可是一份组合；按每部分实际摄入估算后相加，不能整份统一打折 |
| 两人分享一份组合，未描述剩余 | 返回本人完整分配份额；不因组合内部有多种食材再次分摊 |
| 同一菜多角度照片，旁边还有另一道菜 | 同一实物只计一次，另一道菜保留独立条目 |
| 容器／配料关系确实看不清 | 说明最有证据的分组假设，不虚构套餐或为所有情形强行合并 |
