称伴 · ScaleMate 0.4.1 正式版修复食物识别长推理等待、照片修改后的再次分析和兼容服务错误恢复。

### 本版变化

- DeepSeek OpenAI 兼容服务默认关闭推理，减少正文开始前的长时间等待；若网关明确拒绝 `reasoning_effort`，应用会自动移除该参数并重试一次。
- 流式解析支持 `reasoning_content`、`reasoning` 和 Anthropic `thinking_delta`，并扩大长推理流的安全边界。用户主动选择推理模型时也能看到真实进度，不再在正文出现前误判失败。
- 等待期间同时显示首 Token、输出与推理 Token 的粗略估算。完成后的结果卡继续使用服务实际返回的 usage，不把估算值当作计费数据。
- 图片压缩后显示实际尺寸、文件体积和位置信息移除结果，便于判断上传内容。
- 模型偶尔返回 1-based、部分越界或不可用的图片索引时，应用会尽量修正并安全回退到所选照片，不再因此重跑整次识别。
- 无效响应最多自动重试一次；首次返回空食物列表时再尝试一次，第二次仍为空才提示未识别到食物。
- 照片没有变化时再次分析会以上次结果作为修改基线；增删或替换照片后会清空旧结果、建议、usage 和耗时，按当前照片重新分析，同时保留标签和分食人数。
- 食物识别输出预算明确为 4096 Token。它只限制生成结果，不限制照片和 Prompt 的输入上下文；普通输出约 700 Token，仍保留足够余量。

### 已知问题

- 不同 OpenAI／Anthropic 兼容服务的推理开关、流式格式、缓冲策略和 usage 返回存在差异；部分服务仍可能较晚返回正文或只提供粗略进度。
- 本轮真实供应商验收集中在 DeepSeek OpenAI 兼容服务。其他模型或网关的推理关闭行为、首 Token 延迟和长连接稳定性仍需分别验证。
- 最多可添加 6 张照片，每张压缩到最长边 1024 px、JPEG 质量 70；单张上限 1.5 MB、合计上限 8 MB。极端多菜品输出仍可能接近 4096 Token，输入上下文也可能受供应商限制。
- 图片营养、份量和建议均为 AI 估算，受照片质量、遮挡和隐藏用油影响；模型每次重新生成可能出现数值波动，保存前仍需核对食物、克数、营养和份量。
- 照片变化后的再次分析使用“移除后添加”完成替换，当前没有独立的一键替换控件。
- 公共 GitHub 下载代理可能限流、缓存或停止服务；线路测速只反映当前网络，不能保证长期可用性。

### 安装与升级

下载 **ScaleMate.apk**，需要 Android 14 或更新版本。本版 versionCode 为 20，高于 0.4.1-preview.1（code 19）、0.4.0（code 18）和 0.4.0-preview.4（code 17）。正式版与公开预览版共用 `app.scalemate`、绿色图标和固定发布签名，可正常覆盖升级；请勿为安装而卸载仍有数据的应用。

已安装预览版的用户可直接升级到本正式版。正式通道不接收预览版，预览通道会继续接收版本码更高的正式版；切回正式版后不支持降级。更新检查在应用启动或回到前台时执行，不包含关闭 App 后的后台定时任务，系统安装仍需用户确认。

橙色调试测试版 `app.scalemate.fooddev` 与公开包隔离，数据不会自动合并。旧 debug 签名包不能直接覆盖为公开版。

### 隐私与费用

饮食照片识别使用你配置的外部 AI 服务，可能产生费用；手动饮食记录、食物库、蓝牙称重和健康页本地指标不依赖 AI。照片会先在设备上压缩并移除 EXIF／位置信息，再发送给所选服务。照片未变化时再次分析会发送上次分析结果作为修改基线；切换服务或新增发送数据前请核对对应同意范围。

Health Connect 读取仍只包含你主动选择并在系统中允许的类别。健康 AI 分析、对话、导出和主动提醒在本版关闭，不会把健康摘要发送给 AI 服务。
