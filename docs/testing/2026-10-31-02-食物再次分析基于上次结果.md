# 食物再次分析基于上次结果

- **日期**：2026-10-31
- **基线**：`main` 当前工作区，未提交
- **性质**：同一批照片再次分析时，把上次待确认结果作为基线，只按本次补充说明修改相关项，完成后整体替换本次结果
- **证据目录**：[food-revision-evidence](2026-10-31-02-food-revision-evidence/)

## 用户要求

用户希望在照片没有变化时重新分析，AI 能看到之前的分析结果；本次输入只描述要改什么，例如“米饭再少一半”，未提到的食物保持不变。分析期间应继续看到旧结果，完成后用完整的新结果替换待确认结果，不能把未改食物重复追加到餐食。

## 实现

- `AiClient.recognizeDetailed()` 增加 `previous` 和 `previousAdvice`。有旧结果时在系统 Prompt 中加入 `REVISION MODE`：旧结果是基线，当前修改要求和照片证据优先；未提到的食物保持名称、分组、本人克数、营养、份量和建议；禁止追加未改食物的重复副本，最终仍返回一份完整的新结果。
- 请求体先发送本次修改要求与照片，再发送上次分析数据。上次数据包含旧上下文、食物名称、个人克数、个人营养、份量、估算说明、食用建议和整餐建议；用户编辑过的倍率先归一化为有效本人摄入，避免把旧分食系数再次传给模型。
- `FoodViewModel.analyze()` 重新分析时不再清空 `results`、`advice` 或 `usage`，成功后才整体替换；失败、取消或中断保留旧结果。
- 结果页在编辑和分析期间继续展示上次结果；输入框切换为“本次修改要求”，按钮和提示明确“基于上次结果重新分析”。分析完成后恢复常规确认流程。
- 中英文文案和 [食物 AI 记录 PRD](../11-称伴食物%20AI%20记录产品需求文档.md) 已同步。再次分析真实 AI 入口补充到 [Prompt 基准样例](fixtures/food-prompt-baseline/README.md) 和 [测试与验收指南](../02-测试与验收指南.md)。

### 真实 AI 边界

按 Prompt 改动规则执行了基准方法和再次分析方法的命令，但模拟器目标应用私有目录没有 `ai-validation-private.json`，两项均被 JUnit `AssumptionViolatedException` 跳过。不能记为真实模型通过，也不能用 Mock／固定响应替代；取得用户授权的私有服务和测试配置后，应重新执行：

```sh
adb -s emulator-5556 shell am instrument -w \
  -e class 'app.scalemate.FoodAiIntegrationTest#privateFixturePromptBaselineChineseAndEnglish' \
  app.scalemate.test/androidx.test.runner.AndroidJUnitRunner

adb -s emulator-5556 shell am instrument -w \
  -e class 'app.scalemate.FoodAiIntegrationTest#privateFixtureRevisionUsesPreviousResult' \
  app.scalemate.test/androidx.test.runner.AndroidJUnitRunner
```

## 限制

- 模拟器验证的是请求合同、状态保留和结果替换，不代表真实模型一定理解所有修改表达。
- 未执行真实 AI 基准和再次分析，不能宣称分组、语言、营养或模型服从率通过。
- 截图来自 Mock 服务和隔离测试版；真实 AI 响应波动、网络超时和用户实机相册仍需后续验证。
