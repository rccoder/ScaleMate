# Android 包安装与测试环境约定

> 当前只维护正式版、公开预览版、开发调试用测试版三种。历史包名用于兼容已有安装，不代表更多产品版本；当前操作按本页与代码执行，历史过程见 [项目演进](20-项目演进.md)。

## 产品版本与工具

| 类型 | 身份与构建 | 数据、图标与安装 |
| --- | --- | --- |
| 正式版 | `app.scalemate`，固定发布签名，release，正式 Tag | 绿色；保护用户记录，只正常覆盖升级 |
| 公开预览版 | 与正式版相同包名和签名，release，`-preview.N` Tag | 绿色；与正式版共用数据且不能并存；转正要求更高版本码 |
| 调试测试版 | `-PfoodDev` Debug，`app.scalemate.fooddev`，原 debug 签名 | 橙色，显示“称伴 · 测试版”；完整称伴，数据与公开包隔离，不能自动合并 |
| 临时仪器测试工具 | `app.scalemate.test`，显示 ScaleMate Tests | 不是产品版本；核对目标包与签名，完成后清理 |

`foodDev` 和 `.fooddev` 来自历史构建命名，仅为保留数据兼容；不按饮食／称重划分测试版，也不另设“开发版”。旧截图或已发布说明中的旧称呼对应如今的调试测试版，不作为新安装指令。

普通不带隔离参数的 Debug 与正式版共用包名、签名不同，只用于构建检查；不要装到已有正式数据的手机。常规实机测试一律按开发指南带 `-PfoodDev` 构建，不新增包名解决签名冲突。

实机验收先复用手机上已有的橙色隔离测试版 `app.scalemate.fooddev`，默认覆盖安装，不新建 Test 壳或临时 App。安装前核对包名、同一 debug 签名、版本与现有数据；需要只读数据摘要时，优先通过已有 App 的 `run-as` 或经确认的临时工具完成。`app.scalemate.test`、ScaleMate Tests 仅用于明确列出专项仪器测试的场景，不是每次 UI 验收的默认步骤，且本轮结束立即清理。

## 手机操作与数据保护

1. 先检查 `adb devices -l`、屏幕、前台及实际安装清单；多设备必须指定 serial。无线失联先重新发现，锁屏请用户解锁。
2. 保留正式及测试版的记录、草稿、设备、服务与默认选项。只清理本轮创建且已获授权的样例；测试版也可能有用户数据，不能当作都可卸载。
3. 安装仪器测试前核对 `targetPackage`。基础测试针对隔离包；对正式数据做只读升级对比时必须针对 `app.scalemate`，工具使用固定发布证书，显式开启 capture／verify／cleanup。不能用隔离数据库冒充真实数据保留。
4. 系统拒绝安装时看实际错误和正常系统确认，不循环重试或关闭安全机制；不卸载业务 App 解决冲突。
5. 测试后清理临时 APK、夹具和仪器测试工具，恢复屏幕超时及临时偏好。用户明确授予更新器的安装权限按当轮约定处理，不擅自撤销。
6. 证据及时归档到 `docs/testing/`，图片到对应证据目录，不能只放重启会丢失的临时目录。API 密钥、数据库、原始健康数据及私人相册不进入 Git。

## 已清理的历史包

2026-10-18 双通道验收后，手机仅保留 `app.scalemate` 与 `app.scalemate.fooddev`；两者当时均为 code 7，测试版当时仍显示旧名称。旧原型 `app.scalemate.prototype`、旧测试 `app.scalemate.testing`、探测工具 `app.scalemate.nutritionprobe` 和仪器工具 `app.scalemate.test` 已按用户授权删除；`local.scalemate.design` 未安装。本页不是以后批量卸载的授权清单，下一轮仍核对实机。

早期称重视觉稿和探测工程及其安装脚本已移除。健康 AI 设计原型仍保留于 `app/src/prototype/`，属于未来设计、全部模拟；普通回归不安装，仅在明确的设计演示任务中构建，不算第四种产品版本。具体升级、数据验证及清理证据见 [发布验收](testing/2026-10-18-02-应用更新双通道发布与升级验收.md)。
