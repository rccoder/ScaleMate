称伴 · ScaleMate 0.4.0 正式版新增 Health Connect 健康概览、饮食再次分析和更多蓝牙体重秤支持。

### 本版变化

- 新增健康页，从 Health Connect 读取你主动授权的数据，以今日小卡片展示睡眠、心率、心率变异性、步数、运动、体重、营养摄入、活动消耗和距离；可切换近期范围查看变化。没有记录的数据保持未知，不会当作 0。
- 健康读取按日常活动、身体与营养、敏感或临床记录分级选择，读取与写入权限相互独立。首次读取历史后通过变更令牌增量更新，切换页面或时间范围时优先复用本机快照。
- 同一批饮食照片再次分析时会带上一次结果作为修改基线，只需描述要改什么；照片在导入时压缩到最长边 1024 px、JPEG 质量 70，并移除 EXIF 和位置信息。
- 食物图片分析改为读取服务的流式返回。首段正文到达后显示“AI 已开始返回”，等待期间显示首 Token 延迟和粗略输出 Token 估算，完成后使用服务实际返回的 usage。
- 扩展蓝牙体重秤兼容范围，新增云麦、小米、PICOOC、荣耀、realme、Etekcity、FITINDEX 和 OKOK 等系列型号；扫描只展示已识别为兼容协议的设备，并支持同时绑定多台不同的秤。所有型号当前只读取和保存体重。

### 已知问题

- Health Connect 只能返回已授权且实际可读的数据；不同来源应用的睡眠阶段、运动详情、路线、营养和生理指标字段可能不同。运动距离与热量是独立记录，平台不一定绑定到同一次运动。健康数据仅用于日常信息展示，不构成医学诊断或建议。
- 首次查看较长健康范围可能需要在手机上解析并计算较大的本地明细；季度合成样例首次打开 90 天约需 8 秒，实际耗时取决于设备、来源和记录密度。
- 除云麦智能体脂秤 3 SE（YMBS-M263）外，新增体重秤型号目前完成协议单元测试和 API 36 模拟器 Mock 交互验收，仍需在更多真实设备、固件和断线重连场景中逐步确认。同品牌其他型号不因此自动获得兼容承诺。
- 不同 OpenAI／Anthropic 兼容服务的流式格式、缓冲策略和 usage 支持并不一致。部分服务可能直到完成时才返回正文或完全不返回 Token 用量，实际延迟仍取决于网络、图片大小、模型和供应商。处理中 Token 数为粗略估算，不能用于计费或额度判断。
- 图片营养、份量和建议均为 AI 估算，受照片质量、遮挡和隐藏用油影响；模型也可能返回不完整结果。保存前仍需核对食物、克数、营养和份量，不能代替称量或专业评估。
- 公共 GitHub 下载代理可能限流、缓存或停止服务；线路测速只反映当前网络，不能保证长期可用性。

### 安装与升级

下载 **ScaleMate.apk**，需要 Android 14 或更新版本。本版 versionCode 为 18，高于 0.4.0-preview.4（code 17）和 0.3.3（code 13）。正式版与公开预览版共用 `app.scalemate`、绿色图标和固定发布签名，可正常覆盖升级；请勿为安装而卸载仍有数据的应用。

已安装 0.4.0 预览版的用户可直接升级到本正式版。更新检查在应用启动或回到前台时执行，不包含关闭 App 后的后台定时任务，系统安装仍需用户确认。预览通道仍会接收版本码更高的正式版；是否继续尝鲜可在「设置 → 当前版本」调整。

橙色调试测试版 `app.scalemate.fooddev` 与公开包隔离，数据不会自动合并。旧 debug 签名包不能直接覆盖为公开版。

### 隐私与费用

健康页只读取你主动选择并在系统中允许的 Health Connect 类别，不读取称伴本地未同步的餐食、体重或草稿来补缺；撤销读取权限会停止后续同步，不会删除已写入 Health Connect 的记录。健康 AI 分析、对话、导出和主动提醒在本版关闭，不会把健康摘要发送给 AI 服务。

饮食拍照识别使用你配置的外部 AI 服务，可能产生费用；手动饮食记录、食物库、蓝牙称重和健康页本地指标不依赖 AI。照片会先在设备上压缩并移除 EXIF／位置信息，再发送给所选服务。再次分析会发送上次分析结果作为修改基线；切换服务或新增发送数据前请核对对应同意范围。
