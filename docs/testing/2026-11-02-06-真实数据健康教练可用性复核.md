# 真实数据健康教练可用性复核

> 日期：2026-11-02
> 分支：`codex/health-coach-follow-through`
> 范围：使用模拟器中导入的用户健康快照和真实模型，复核健康教练追问、来源展示、临时计划调整及记忆候选；目标是判断“能不能用”，不是只验证接口成功。

## 一、结论

数据链路已经可用，真实模型连续 5 轮无失败，单轮约 3.7～5.7 秒。最终回答能区分“可以规划”“只能看旧趋势”“不能判断训练质量”，能正确生成当天缩短计划、周六临时改期和待确认记忆。

但当前仍不是成熟的 Google Fit 式教练。用户数据偏旧，力量训练只有总时长，没有动作、重量、组数和 RPE，因此教练经常只能说明“记录不足”。真实模型的回答长度和引用数量仍会波动；复杂问题可能出现约 400 字和多条依据，需要继续控制。

## 二、首次真实运行暴露的问题

1. 生产界面只删除了证据 ID，没有先把准确值渲染回正文；记录里保存的也是内部别名，导致来源卡片找不到证据。
2. 模型会把近似值和证据值重复展示，例如先写一个近似时长，紧接再由引用显示精确时长。
3. 模型不确定当天星期时，曾把周一误判为“不是计划训练日”；同一天又生成了当天的缩短计划，正文与候选互相矛盾。
4. 模型偶尔把记忆候选扩写成用户没有说过的计划或器械内容。
5. 模型曾返回缺少 `evidenceId` 的 `claims` 项，旧逻辑让整轮失败；正文引用本身是可用的。
6. “记住：我不喜欢跑步”曾有一次没有返回记忆候选。这种明确命令不应依赖模型随机性。
7. 早期回答偏报告式，常列出多项无关指标、重复限制和两条以上建议。

## 三、本轮修复

- 教练回复先按证据别名渲染准确值，再把来源 ID 映射回本地快照 ID；正文和来源卡片都能正常显示。
- 清理短伪引用、长伪引用、内部字段名、字面量 `evidenceId` 和重复建议。
- 新增重复测量清理，避免近似值紧挨着准确值重复出现。
- Prompt 输入增加权威字段 `todayWeekday`、`todayScheduled`，禁止模型自行换算计划日。
- 用户明确给出更短可用时间时，要求生成当天的临时缩短计划。
- 临时改期的 `date` 必须是目标日期；真实测试明确检查周六。
- 记忆候选只保留用户原句中的明确片段；模型遗漏时，对“记住……”命令提供本地待确认候选兜底。
- 缺字段的 `claims`、未知证据别名、短引用和 `evidenceId:...` 写法改为安全忽略，不再无谓中断整轮。
- 收紧追问输出：直接回答、最多两条关键理由、优先 1～2 个证据引用；简单周运动量问题只保留一条建议。

- 模型：`workbuddy/deepseek-v4.1-flash`

- 目标与记忆：测试使用合成设置，不写用户长期目标。
- 推理：OpenAI 兼容请求关闭 DeepSeek 推理。

## 七、未解决与边界

- 健康快照的数据日期明显偏旧，运动记录缺动作、组数、负重和 RPE，教练无法判断力量训练质量；这是数据能力问题，不是靠 Prompt 能补齐。
- 用户尚未设置长期训练目标时，教练只能建议先设置频率或继续记录，价值仍有限。
- 真实模型仍可能输出偏长的复杂回答，也可能漏候选；本轮已增加本地兜底，但不能保证所有供应商和表达稳定。
- 本轮没有重新做真机 Health Connect 授权、覆盖升级或公开发布验收。
- 本轮没有修改饮食识别 Prompt，因此无需执行四张饮食基准图。
