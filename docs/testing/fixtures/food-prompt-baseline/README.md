## 每次 Prompt 改动后的真实 AI 检查

必须使用当次目标模型和已获授权的私有服务配置，逐张运行真实图片识别。至少检查：

1. 返回一个可解析的 `calculationMode=personal` JSON 对象，`foods` 非空，每项都有 `name`、`personalNutrients` 和本人摄入说明。
2. 宫保鸡丁和米饭不能合并为一项，也不能额外拆出花生、辣椒或葱；番茄炒蛋和米饭同样不能合并或拆成原料。
3. 汉堡薯条不能拆成汉堡配料；早餐不能拆成鸡蛋、培根和松饼的原料级组件。允许的两种分组粒度见上表，但同一次结果不能既有一份套餐又重复列出其组成。
4. 不得重复计数同一食物；`imageIndices` 必须为合法的零基图片下标。
5. 中文请求返回中文名称与建议；英文请求的名称、说明和建议不夹带中文。
6. 两人均分、本人只吃自己份额的一部分等文字条件，仍由模型直接返回最终本人摄入；应用端不得再次分摊。

每轮记录实际模型、服务格式、运行日期、通过／失败／跳过、首次失败与重试、返回的菜品名称和分组，以及无法判定的边界。固定响应测试通过不能替代本组真实模型测试；模型输出有波动时不能只保留成功样本。样例图只验证结构、分组、语言和合同，不把营养值当作标准答案。

## 再次分析基线检查

再次分析属于新的 Prompt 合同，不能只验证首次识别。真实 AI 入口：

```text
FoodAiIntegrationTest#privateFixtureRevisionUsesPreviousResult
```

方法先用 `kung-pao-chicken-with-rice.png` 正常识别，随后把上次完整结果、上次上下文和“本次只删除米饭，保留宫保鸡丁”的修改要求一起发送。通过时必须满足：

- 宫保鸡丁仍然保留，且只出现一次；
- 明确要求删除的米饭不再出现；
- 最终返回完整的新结果，不把未改食物重复追加；
- 请求中的本次要求优先于上次结果，上次结果只作为基线。

该方法同样依赖目标应用私有 `ai-validation-private.json`，没有配置或授权时只能记录为跳过，不能算真实模型通过。
