## 用户问题

用户选择刚拍摄的食物照片后，正式版曾出现：

- 经常等待约一分钟，偶尔成功；
- 等待期间看不到首 Token、已接收 Token 或图片压缩结果；
- 服务明明返回了推理流，界面仍停在“正在识别”；
- 兼容模型偶尔返回可修正的字段差异，却导致整次结果作废并重新请求；
- 第二次请求重新生成全部内容，用户感受到的速度被进一步放大。

目标不是只把超时调大，而是让成功路径真正快、兼容错误可恢复、等待文案不误导。

## 根因

1. DeepSeek 默认会先生成大量 `reasoning_content`，正文可能迟迟不出现，甚至先撞到 `max_tokens`。
2. 旧 SSE 实现把整个原始流限制在约 1 MB；长推理会在正文前触发上限。
3. 旧实现只监听正文 `delta.content`，没有把已到达的推理流反馈给界面。
4. 兼容模型偶尔把 `imageIndices` 写成 1-based，原解析器把整个结果判为无效。
5. 无效结果自动重跑时，用户只看到重新计时的进度，误以为服务一直很慢。

## 最终修复

- 对支持 reasoning level 的 DeepSeek OpenAI 兼容服务发送：

  ```json
  {"reasoning_effort":"none"}
  ```

- 不再使用实测无效的 `thinking.type = disabled`。同一模型实测该字段仍持续输出纯推理并在 `max_tokens` 截断。
- 若兼容网关明确拒绝 `reasoning_effort`，自动移除该字段并重试一次，避免破坏不支持该参数的供应商。
- SSE 仍支持 `reasoning_content`、`reasoning` 和 Anthropic `thinking_delta`，以便用户主动选择推理模型时显示真实进度。
- 首次返回 `foods: []` 时自动重试一次；第二次仍为空才提示未识别到食物，降低明显有食物时的误判空结果。
- `imageIndices` 兼容 0-based、1-based、部分越界和完全不可用四种情况；能修正就修正，不能修正时安全回退到所选照片，不再因为图片索引格式差异重跑整次分析。
- 解析失败日志只记录字段原因、输出长度和尝试次数，不记录照片、食物名或原始响应。
- 等待卡先显示“通常几秒到十几秒”，随后显示：
  - 首 Token 延迟；
  - 当前粗略输出 Token 估算；
  - 本机压缩后的尺寸、体积及已移除位置信息；
  - 服务完成后改用真实 usage，不把估算值冒充计费值。

本轮没有修改食物识别 Prompt，因此没有重新执行 4 张真实 Prompt 基准样例。

## 真实供应商参数对比

使用同一张压缩后的照片和同一模型，在主机上直接比较控制字段：

| 参数 | 完成时间 | 推理 Token | 正文 | 结束原因 |
| --- | ---: | ---: | ---: | --- |
| 不传 reasoning 字段 | 6.24 秒 | 512 | 0 字符 | `length` |
| `reasoning_effort: none` | **2.34 秒** | **0** | 217 字符 | `stop` |
| `reasoning_effort: low` | 5.41 秒 | 512 | 0 字符 | `length` |
| `thinking: {type: disabled}` | 5.90 秒 | 507 | 10 字符 | `length` |

结论：该网关接受 `thinking` 字段不等于它生效；`reasoning_effort: none` 才是能实际关闭推理的字段。

| 轮次 | 总耗时 | 重试 | 首 Token | 估算热量 | 输出 Token |

结果：

- 5/5 返回有效食物结果，无空结果、无截断、无自动重试；
- 总耗时稳定在 **6.8–7.5 秒**；
- 首 Token 在约 **2 秒**内出现；
- 等待期间持续显示 Token 估算和压缩结果；
- 识别结果包含面条、蔬菜等可见内容，估算值随模型每次重新生成存在合理波动，不应把单次热量当作营养准确率基准。

### 修复前观察

- 第一轮真实分析耗时 17.2 秒，并观察到一次自动重试。
- 第四轮真实分析耗时 14.6 秒；日志明确记录首轮失败原因：

  ```text
  recognition parse failed: attempt=1 type=InvalidRecognition reason=imageIndices
  ```

- 修复 `imageIndices` 兼容后，后续 5 轮均未再重试。

### 选图控制

一次中间验证中，系统相册首张缩略图变成了汉堡样例，按固定坐标选择后识别出汉堡和薯条。该结果说明模型对实际选中的图片识别正确，但该轮不计入目标照片统计。最终验证改为按系统选择器的 `content-desc` 定位目标动态照片，不再依赖网格顺序或坐标。
