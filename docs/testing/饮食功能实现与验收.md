# 饮食功能实现与验收

2026-10-17，当前工作区开发版本。本文记录真实功能的实现与验收；此前纯 Mock 原型另见 [AI 功能交互原型](AI%20功能交互原型.md)。截图中的餐食均为验收样例，不代表用户的实际摄入。

## 本轮实现

- 默认进入「记录」：当天饮食、体重、时间线、待同步数量；保留记录、饮食、称重、设置四个 Tab。
- 首次进入只说明本地记录、按类别授权和 AI 数据发送；添加秤、试称和设备确认放在称重路径。
- 饮食支持手动录入、拍照、系统照片选择器、补充标签与描述、逐项修改、常吃食物、历史复用、日期餐别、修改与删除。
- 图片 AI 估算必须逐项确认。整份营养与个人摄入分开保存，明确比例以整份还是自己分到的份量为基准；复用不会再次应用旧的均分比例。
- 多个 OpenAI／Anthropic 兼容服务、密钥加密、图片能力声明、默认服务与当前选择、连接测试、首次发送同意。远程地址要求 HTTPS；用户配置的私有 IPv4 地址可使用 HTTP。
- 每餐先写入 SQLite，再通过营养权限写入 Health Connect。稳定客户端 ID 与递增版本用于修改；删除支持仅本地或同时删除健康记录；失败任务持久化、可重试。
- 没有图片服务时可配置服务、转手动或复用；没有绑定秤时进入添加引导；未授权营养写入时先本地保存再提示授权。

健康 AI 分析、健康 JSON / Prompt 导出属于另一份 PRD，不在本轮功能交付范围内。

实机选择图片的具体步骤与自动化注意事项：[Android 实机图片选择操作](Android%20实机图片选择操作.md)。

## 2026-10-17 饮食流程重构（当前）

用户确认：常吃与历史合为食物库；普通食物保留最近 500 个、常吃额外保留。同名合并，常吃基准不被新餐覆盖。成功保存新餐才增加使用次数，同一餐同名食物算一次；修改旧餐和取消不增加。

- 首页仅保留日期、已记录汇总、餐次和记录入口；AI 设置按使用场景提示。
- 一餐组合拍照、相册、添加食物。照片每批最多 6 张；默认同一餐，重复角度合并。照片、描述、分析状态、结果作为独立批次持久化。
- 结果在原添加页核对并编辑，默认紧凑摘要，可在当页展开。确认后才加入餐食；已有餐食项目编辑使用“确认修改”替换原项。
- 分食只换算一次：2 人均分、米饭吃自己那份 1/3 为整份 1/6；明确整份 1/3 则为整份 1/3。UI 展示个人实际份量和营养。
- 复用无需调用 AI。缩略图保留于食物库，历史餐食列表不带图。图片显示缩小解码，食物库每页 20 条，避免大量图片同时加载。
- 当前自动餐别：5–10 点早餐、11–14 点午餐、17–21 点晚餐，其余加餐，可修改时间与餐别。

## 构建与复验

```sh
gradle -PfoodDev :app:assembleDebug :app:testDebugUnitTest :app:assembleDebugAndroidTest
python3 scripts/check_i18n.py
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r -t app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w -e class app.scalemate.StoreTest,app.scalemate.FoodStoreTest app.scalemate.test/androidx.test.runner.AndroidJUnitRunner
```

`-PfoodDev` 仅改变应用 ID 与显示名称，不包含凭据。正常构建不带此参数。测试 APK 使用 `app.scalemate.test`，安装前确认其目标构建一致。

真实服务集成用私有临时夹具主动开启，缺失夹具时跳过；Health Connect 集成需 `testNutrition=true` 且已有营养写入权限。密钥、原始响应、设备数据库与临时照片不进入仓库。开发包保存的服务密钥由 Android Keystore 加密；测试夹具执行后清除。

## 2026-10-18 最终方案：AI 负责本人摄入，应用不二次换算

发现用户实际草稿只有两人均分、无标签或说明，但旧模型输出 consumedFraction 0.5，旧应用再除人数，导致整份 1/4。按用户最终确认，取消应用自动分食／食用比例计算：AI 直接返回 calculationMode personal、personalGrams、personalNutrients、intakeSummary，应用原值保存。不存在依据模型旧 shareCount／consumedFraction 二次换算的新路径；旧合同不完整时拒绝结果，历史保存值不自动迁移。

输入支持单独、两／三人和其他人数，并补充“没吃蘸料”标签；描述用于指明个人碗／饮料、剩余和成分排除。新增过的应用份量规则与专门比例编辑器已撤回，不作为最终实现。旧待确认记录提示重新分析。默认摘要仍可展开三组，第三组改为 AI 原始本人摄入快照；上下图标替代文字符号。
