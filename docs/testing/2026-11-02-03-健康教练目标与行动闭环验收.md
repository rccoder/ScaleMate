# 健康教练目标与行动闭环验收

- 日期：2026-11-02（Asia/Shanghai）。
- 基线：`v0.4.2 / code 25`，发布提交 `4eb61e6`；本轮在 `codex/health-coach-follow-through` 迭代，尚未公开发布。
- 用户指定主要竞品为 Google Fit；本轮目标是让用户知道今天做什么、能执行、下次能依据反馈调整。

## 原功能是否解决问题

原实现能解释已读取的指标，提供一个建议，解决了部分“数字看不懂”的问题。但它只保存最近一段回答，缺少易用的目标入口、可执行行动的状态和回访。每次生成都重新从数据出发，无法知道用户是否采纳、没做到还是觉得太难；刷新后快照 ID 变化还可能让旧建议消失。这更接近一次性数据点评，不能当作完整 AI 教练。

另外，数据口径直接影响可信度：比较可能混用来源，压缩后的分组仍引用未发送的原 ID，模型有时把历史数据说成当前状态，或把“从本地中午开始计数”的睡眠时刻误读为午后入睡。真实模型验证还发现重复单位、过长复述指标与中文时长措辞问题。这些不能靠增加一段鼓励文案解决。

## Google Fit 对标与边界

参考 Google 的[目标说明](https://developers.google.com/fit/android/using-goals)、[Fit 数据与目标总览](https://blog.google/products-and-platforms/products/google-fit/healthier-more-active-life/)、[活动追踪帮助](https://support.google.com/fit/answer/6075066?hl=en)。这些资料分别支持每日步数／Heart Points 目标、每日与每周进展和汇总、运动记录与实时统计等能力，不据此声称 Fit 拥有对话式 AI 教练。

Google 目前正式介绍的生成式教练属于 [Google Health Coach](https://blog.google/products-and-platforms/products/google-health/google-health-coach/)，涉及了解用户背景、调整计划与及时反馈；它与 Google Fit 需要区分。按用户指定，本轮以 Fit 为主要产品对标，借鉴教练的持续跟进方式，不把其他产品能力混称为 Fit 已有功能。

| 用户问题 | 对标启发 | 原称伴的差距 | 本轮处理 |
| --- | --- | --- | --- |
| 我在为什么努力 | Fit 提供明确目标 | 目标设置入口跟随旧健康 AI 被隐藏 | 独立“我的安排”，开放可选数值目标，关注规律、睡眠、活动或体重理解 |
| 今天该做什么 | 从目标看到当前进展 | 一段建议难采纳、难记住 | 一条行动，带时间或场景提示；本人决定是否采纳 |
| 做了之后怎么办 | 进展是持续体验 | 无行动状态，下一次不记得 | 采纳／完成／没做到／太难，近 7 天按天确认进展 |
| 不适合我怎么办 | 个人目标与日常安排应可调整 | 不考虑可用时间和执行阻力 | 通常可用时间、当天感受、下次生成参考近期反馈 |
| 数字可靠吗 | 看清来源、时间和记录类型 | 历史和当天、测量与解释容易混淆 | 新鲜度元数据、明确睡眠时刻语义、同来源比较、记录摄入限制 |
| 能否代替运动 App | Fit 有实时运动追踪 | 称伴不是实时运动记录器 | 不伪造 Heart Points、实时配速、训练负荷或临床恢复分数 |

现有 Health Connect 快照能支持睡眠时长／作息、步数、运动频率时长、同口径 HRV、体重记录及已记录营养的有限观察，具体取决于授权、覆盖与来源。它不能证明用户主观状态、饮食是否完整、运动强度是否适合本人或建议是否有效。单次体重、单个 HRV、部分当天步数都不足以支持相应强结论。

## 本轮实现

- 目标、时间和当天感受由用户选择；疲劳自报次日失效，体重方向不默认减重。没有新增自动学习的长期偏好或后台 AI。
- 回答拆成简短观察与单一行动；校验仅一条行动和证据引用，拒绝凭空数字与未知依据。反馈只写本地，主动再次生成才带入上下文。
- 已完成当天同一目标的行动后，再更新只更新解读，保留原行动与完成状态，不反复加码；明确更换关注方向后才可提出新行动。
- 保存近 7 天、最多 14 条行动，发送最多最近 5 条。完成天数按本人确认去重，不把生成次数计成进度，不把完成等同于健康改善。
- 旧行动在刷新、重新生成、失败和取消时保留；旧日期明确标为上次行动，重建模型后保留反馈与安排。
- 新增 `coach-v2` 发送同意范围；旧同意不自动授权安排和反馈。按实际仍可用类别过滤旧行动，清除教练内容不删除健康缓存、业务记录、AI 服务或数值目标。
- 修正压缩分组 ID 与短证据别名不一致，补入可读 Nutrition 已记录数据，排除会被误当总量的原始中位数；单次体重也允许进入建议，但不能伪造趋势。
- 明确每类测量日期、新鲜度和真实本地睡眠时刻；拒绝未来／无效日期，避免用最新读取时间代替测量时间。缩短解释，防止重复单位。
- 今天和昨天都没有测量时，使用可信的本地说明替代模型对当前状态的判断；只保留经校验的一般行动。新测量的解释移除内嵌 ID，将精确测量值放在可点开的参考标签里，避免数值生硬拼进否定句。

## 真实 API 迭代与失败记录

使用模拟器既有橙色隔离测试版和现有 Health Connect 活跃快照，没有备份手机或导出数据库。测试中的目标、时间和疲劳感是验证场景，不当作用户真实自报。

1. 首次 live 前置检查错误地将所有本地地址视作 Mock，未发出模型请求；核实当前服务是 `magpie` 本机转发后修正检查。已撤回要求用户重新配置的判断。
2. 原选定 `workbuddy/deepseek-v4.1-flash` 实际调用失败，最小探测返回 429 和用量频率限制。随后测试临时使用同一服务内的 `deepseek/deepseek-v4-flash`，不修改保存的服务或默认模型。
3. 第一轮三个请求虽成功返回，但测试夹具的历史类别包含未发送类别，反馈被隐私过滤；修正为实际发送事实的类别，并断言第二、三轮确实携带一、两条反馈后重跑。不能把首轮独立回答算作闭环通过。
4. 第一轮真实反馈回归暴露历史数据措辞、睡眠时刻解释和冗长复述问题；补充本地新鲜度与时刻含义后再次迭代。网络／模型成功不等于内容质量通过。
5. 原单测有一条仅期待步数、排除 Nutrition 的旧合同，按本轮明确的饮食输入范围修订；新增夹具一度使用未补零日期，修正为 ISO 日期并在生产路径排除非法日期。曾出现 5 项同源夹具失败，修正后全量通过。
6. 历史数据模式曾因未展示的模型解释含额外数字而拒绝整份回答，完整页面测试首先表现为等待超时；现仅在此模式丢弃模型解释和声明，仍严格校验行动和引用。新测量模式继续要求可核对的依据，不放宽全局健康回答校验。

## 最终验证

- 普通 Debug 与隔离测试构建均通过 326 项 JVM 单测，0 失败、0 错误、0 跳过；Lint 无错误、141 条告警，877 对翻译校验通过。普通 Debug 没有安装到公开包。
- API 36 模拟器最终 6 项仪器测试通过，无跳过：4 项固定组件交互、1 项真实模型回归、1 项完整健康页与真实 ViewModel／模型流程。见[设备结果](2026-11-02-03-health-coach-evidence/device-results.txt)和[本地检查](2026-11-02-03-health-coach-evidence/local-checks.json)。
- 使用现有 Health Connect 活跃快照和实际配置服务的临时模型覆盖，三轮分别发送零、一、两条反馈；17 个事实，最终样本约 1.9–2.5 秒。快照内是历史测量，应用如实退化为一般习惯建议，不把它冒充当前身体状态。只归档不含测量值和原始回复的[摘要](2026-11-02-03-health-coach-evidence/real-ai-summary.json)。耗时不是速度承诺。
- 另用纯合成的当前日数据调用真实模型：早晨、部分当天步数、较短睡眠、本人报告疲倦及可用五分钟。验证当前证据引用路径，返回轻缓短时行动，不以部分步数评判全天。此场景没有写入 Health Connect，也不是用户当天实测；见[合成数据真实 AI 结果](2026-11-02-03-health-coach-evidence/synthetic-real-ai.json)。
- `HealthCoachFlowDeviceTest` 使用生产 `HealthScreen`、`HealthViewModel`、持久化和真实 API，在独立临时数据库复用已有摘要及服务配置：生成 → 太难 → 修改时间／感受 → 替代行动 → 完成 → 重建后保留 → 模拟本地快照修订 → 请求失败仍保留。数据库在测试后删除，不修改保存的原服务、默认模型或外部健康记录。最后的无效模型是故意触发的失败路径，不当作真实服务自然失败率样本。
- 合成组件测试验证参考标签回调、采纳与完成／撤销／太难反馈、更新时保留、过期行动、安排编辑、英文／深色／大字体。截图使用固定文案与合成测量，不是私人真实 AI 输出：[行动](2026-11-02-03-health-coach-evidence/screenshots/01-action.png)、[完成](2026-11-02-03-health-coach-evidence/screenshots/02-done.png)、[太难](2026-11-02-03-health-coach-evidence/screenshots/03-too-hard.png)、[生成中保留](2026-11-02-03-health-coach-evidence/screenshots/04-generating-keeps-action.png)、[上次行动](2026-11-02-03-health-coach-evidence/screenshots/05-previous-day.png)、[英文深色大字体](2026-11-02-03-health-coach-evidence/screenshots/06-english-dark-large-text.png)。
- 在完整橙色测试版实际核对“我的安排”、新用途同意和数值目标入口；测试后恢复关注方向、时间和疲劳开关。临时仪器工具、私有结果文件和本轮截图夹具清理；原有业务记录、服务及既有夹具保留。本轮不操作用户手机。

本轮只修改健康教练 Prompt，饮食识别 Prompt 未修改，未执行四张饮食基准。真实调用通过不代表健康建议有效率或营养准确率评测，也不覆盖原先被限流模型的兼容性与全部用户设备。

## 仍有的差距

- 当前完成的是每日小行动的短期闭环，尚没有按用户日程安排、自动调整的完整训练周计划。
- 没有实时 GPS／配速或训练过程指导，不能从现有记录复制 Fit 的完整运动体验。
- 没有足够的体能、疾病、受伤、设备和作息背景，不应输出高强度或临床建议；AI 解释质量仍受模型影响。
- 连续使用后是否提高执行率、目标达成或健康结果，尚未验证。需要真实用户使用与回访，不能靠本轮 API 返回速度证明。
