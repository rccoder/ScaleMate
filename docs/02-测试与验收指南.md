# 测试与验收指南

本指南规定可重复执行的方法，单轮结果保留在 [docs/testing](testing) 与对应实机证据目录中。历史记录中的测试数量、截图和方案只代表当时版本，当前行为以代码及最终确认的需求为准。

## 按改动选择验证

| 改动 | 应做验证 |
| --- | --- |
| 文档、产品介绍 | 内容符合当前实现；本地链接、图片存在；`git diff --check` |
| UI、交互、引导 | 相关构建和翻译检查；模拟器关键路径、返回／取消／空状态；发布前或涉及系统外观差异时用真机复核；前后截图；必要时检查中英文、深色模式 |
| 饮食逻辑、存储、同步 | JVM 测试、构建、Lint；相关模拟器隔离测试；需要证明 Health Connect 实际写入或目标应用读取时再上真机；新增／编辑／删除／重启及失败恢复；有意义的合同回归 |
| AI Prompt、协议、图片处理 | 固定响应验证解析／错误处理；**每次 Prompt 改动**用 [4 张基准样例](testing/fixtures/food-prompt-baseline/README.md)跑真实 AI；语言、多人分食与本人摄入；记录不稳定响应 |
| 发版、工作流与校验脚本 | 发布检查脚本及反例测试；实际 release APK 核验；同提交 GitHub CI；正式发布见发布指南 |

不要为了可逆的文案或间距调整编写镜像实现的测试。新增测试应捕捉真实故障，例如返回结果重复分摊、旧数据库迁移丢数据或误发调试测试包。

健康同步的分页和性能变更使用 [季度 Health Connect 夹具](testing/fixtures/health-quarter/README.md)，覆盖超过一页的真实平台记录、连续无变化、重开缓存、时间范围和历史记录修改／删除。区分仅完成故障采集的 `baseline` 模式与包含业务断言的 `fixed` 模式；小样本通过不能替代密集记录验收。

## 本地构建与基础检查

需要 JDK 17、Android SDK 36；`local.properties` 中设置 `sdk.dir`，Java 与 adb 放入 PATH。

```sh
python3 scripts/check_i18n.py
python3 scripts/check_release.py
python3 -m unittest discover -s scripts -p 'test_*.py'
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug --console=plain
```

Lint 告警应评估、记录；不能把“无错误”写成“零告警”。检查报告位于 `app/build/reports/`。普通 CI 自动执行上述检查，不使用签名密钥或调用用户 AI 服务。

需要构建手机调试用的隔离测试版时：

```sh
./gradlew -PfoodDev :app:assembleDebug :app:assembleDebugAndroidTest --console=plain
```

测试版是完整称伴，显示“称伴 · 测试版”和橙色图标；`-PfoodDev` 及包名 `app.scalemate.fooddev` 沿用已有安装，数据与公开包 `app.scalemate` 分开。普通不带参数的 Debug 仅作 CI 构建检查，与正式版同包名、不同签名，不能通过卸载正式版解决冲突。早期原型已移除；保留的健康 AI `prototype` 仅作未来设计演示，不是调试测试版或正式业务验收。

## 模拟器与真机分层

常规业务回归、页面导航、启动／重启、状态恢复和大部分仪器测试优先使用本机 `ScaleMate_API_36` AVD（API 36 Google APIs x86_64）；真机用于硬件、厂商系统或发布门槛，不要求每轮都连接手机。手机 ADB 无法连接、无线调试失联或本轮不涉及硬件时，直接使用模拟器继续验证，不因实机不可用中断可覆盖的功能。模拟器结果与真机结果分开记录，模拟器截图必须注明来源，不能放入 README／Brand 冒充真实手机截图。

| 验证内容 | 模拟器 | 真机 |
| --- | --- | --- |
| 构建、JVM 测试、Lint、数据库与解析仪器测试 | 默认执行 | 仅按专项需要抽查 |
| UI、导航、返回／取消、空状态、语言与深色模式 | 默认执行并截图；发布候选复核关键页面 | 检查厂商系统栏、输入法、字体缩放和实际屏幕差异 |
| 多图导入、编辑、保存、失败恢复 | 使用系统图库／固定样例 | 发布前检查真实相机、相册、实况照片和权限选择器 |
| 云麦秤扫描、广播解析、连接和 5 秒自动保存 | 仅能验证权限、扫描器启动、帧解析和状态机；不能证明设备兼容 | **必须**使用真机与实秤完成 |
| Health Connect 授权、平台写入与目标应用读取 | 已验证 Google APIs API 36 镜像可授权并写入／删除体重记录；不同镜像仍需实测 | **必须**验证实际授权、Google Fit 等目标应用显示和厂商数据行为 |
| 预览／正式覆盖升级、系统安装授权、数据保留 | 不替代正式发布验收 | **必须**按发布指南完成 |

本机已安装 AVD `ScaleMate_API_36`；如果换机器或 SDK 位置，先确认 `avdmanager list avd` 能识别 AVD。非标准 SDK 根目录可能需要把 `image.sysdir.1` 写成镜像绝对路径。启动命令：

```sh
SDKROOT="$HOME/.local/share/health-connect-tools/sdk"
"$SDKROOT/emulator/emulator" -avd ScaleMate_API_36 \
  -no-audio -no-boot-anim -gpu host \
  -no-snapshot -port 5556
```

有桌面会话时保留模拟器窗口，使用 `DISPLAY`／`XAUTHORITY` 指向当前会话并以 `-gpu host` 使用宿主机 GPU；不要用 `-no-window` 后再让用户寻找窗口。纯自动化或无桌面环境可临时加 `-no-window -gpu swiftshader_indirect`，但软件渲染会明显降低交互流畅度，不能据此判断 App 的性能。等待 `adb -s emulator-5556 shell getprop sys.boot_completed` 返回 `1`。页面可通过 `adb exec-out screencap` 和 `uiautomator dump` 核对；需要人工点击时使用 `input tap`，不能把临时坐标当固定操作流程。结束用 `adb -s emulator-5556 emu kill`，不要按手机地址误操作。

模拟器的 BLE 协议栈和扫描器可以启动，但没有真实射频和云麦秤广播源。不得把“扫描器启动未报错”写成“蓝牙兼容通过”，也不得把 Health Connect 平台的写入成功写成 Google Fit 已显示。

## 健康功能本地验证

健康功能的 JVM 测试包括合成统计、提醒规则、JSON／Prompt 导出和本机回环 HTTP 固定响应。Robolectric 用独立模拟 Android 环境验证 SQLite v4 → v5 迁移、原生记录映射、并发初始化和 Compose 页面；不连接真实 Health Connect 或真实模型，模拟安装来源和关闭自动检查更新只作用于测试环境。

```sh
./gradlew -PfoodDev :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest --max-workers=2 --console=plain
```

首次执行 Robolectric 需要下载 Maven 测试运行库。本地渲染原图由 `HealthUiLocalTest` 输出至 `app/build/reports/health-ui/`；归档时注明模拟渲染，不放进 README 的实机截图组。普通不带参数的 CI 测试同样应通过；两种构建顺序执行，避免同时写同一构建目录。

本地通过后仍要核对真实权限、Health Connect 读取／来源去重／历史、密钥与模型、后台／通知、系统文件保存和分享。模拟器可用于功能与页面验证；未在真机执行的硬件、目标应用读取和发布测试不能标记通过。

## 实机隔离测试

安装前先按 [Android 包安装与测试环境约定](04-Android%20包安装与测试环境约定.md) 核对包名、图标、已有数据与清理范围；临时仪器测试工具不应长期留在用户桌面。

先检查 `adb devices -l`，多设备时用 `adb -s <serial>` 指定目标；`emulator-5556` 只用于模拟器，正式／预览／实秤验收必须明确选择真机 serial。确认本次 APK 的包名和安装目标；调试测试版与仪器测试 APK 必须来自同一次、同参数构建。临时工具包固定为 `app.scalemate.test`，切换构建目标后需重新安装匹配测试包。

```sh
adb -s <serial> install -r app/build/outputs/apk/debug/app-debug.apk
adb -s <serial> install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s <serial> shell am instrument -w \
  -e class app.scalemate.StoreTest,app.scalemate.FoodStoreTest,app.scalemate.AiFormatTest,app.scalemate.AiServicesTest \
  app.scalemate.test/androidx.test.runner.AndroidJUnitRunner
```

这些测试使用隔离数据库或本机模拟 HTTP 服务，不等于调用真实 AI。检查测试输出和进程结果，不只看命令是否返回；保存通过／失败数量与必要诊断。`FoodAiIntegrationTest` 单独执行，不混入隔离测试结果。

UI 验收覆盖本次涉及的完整路径，包括空状态、正常完成、取消／返回、失败恢复和重启后状态。饮食重点检查：

- 添加入口三选一、相册多选、缩略图追加／删除、未分析返回及重新进入。
- 真实分析结束后当页能看到结果，编辑营养、移除、星标、展开／收起，确认后才加入餐食。
- 一餐总计、日期／餐别、保存后的记录与食物库复用；新餐计数、旧餐编辑不重复计数。
- 未配置图片 AI、缺健康权限、同步失败的提示与本地保存；需要真实写入时明确操作的是测试餐食，核对同步状态并清理自己创建的数据。
- 本人摄入由 AI 直接返回，应用不再按人数二次分摊；解析测试证明数据通路，不能证明照片营养准确率。
- 相册实况照片需选择一张带 Motion Photo／视频尾部的真实样例，确认导入后只保留静态主图且能完成识别；不能用普通 JPEG 代替。

## 专项仪器测试

不要用不带类筛选的全量 `am instrument` 代替基础隔离测试。按用途显式执行：

| 测试 | 目标与前提 | 清理与结果边界 |
| --- | --- | --- |
| `UpdateArchiveTest#androidReadsFixedSignerFromRealReleaseApk` | 隔离测试版私有 files 目录预置同一 Release 的 `update-validation.apk`、`update-validation.json`、`update-validation.json.sig`；显式指定该方法 | 真实附件校验，缺夹具会失败；finally 删除三份夹具，不上传业务数据 |
| `UpdateRouteProbeDeviceTest#smallSamplesOnRealNetwork` | 指定类与 `-e probePublicRoutes true`；当前源码样本 Tag 固定为 v0.2.1 | 实际公网小样本，不是本轮新包整包验证；不把未启用的跳过算成功 |
| `UpdateUpgradeDataTest` | 指向正式包的固定发布签名仪器工具，显式 capture／verify／cleanup，参见发布指南 | 只读业务数据摘要比较；不安装普通 Debug 到正式包，不导出记录／密钥 |
| `FoodAiIntegrationTest#<method>` | 明确选择方法，按下节准备私有配置与图片；模型／格式以该方法源码为准 | 真实外部服务调用，可能计费；夹具缺失会跳过，不能当作真实 AI 通过 |

附件夹具可先放本轮临时目录，再用隔离测试版的 `run-as` 复制进其私有 files；从实际 Release 下载并核验，不把 APK 或私有配置提交到 Git。用完删除本轮手机临时文件。准备、首次失败、跳过、重试和最终结果分别记录。

打开业务 App 会执行其正常同步／前台逻辑，有授权与待同步任务时可能写入 Health Connect。界面测试不能声称启动、截图或切换语言天然无健康副作用；测试前按实际数据和授权选择环境，保护已有记录。

## 手机操作与截图

无线调试端口会变化，先用 `adb mdns services` 发现，再 `adb connect <当前地址>`。不要循环重试已拒绝的旧端口。手机锁屏需用户解锁，锁屏后的旧 UI 树不能作为可操作证据。必要时记录并临时调整屏幕保持唤醒设置，结束后恢复，不长期改动用户设备。

从系统相册选图前阅读 [Android 实机图片选择操作](testing/01-Android%20实机图片选择操作.md)：本机点击缩略图中心可能进入预览，多选需点击图片角上的 checkbox；检查“已选择 N 项”，确认后再检查 App 缩略图数量。其他机型以当前 UI 为准。

截图保存至 `docs/screenshots/current/` 或对应 `docs/testing/` 证据目录，按已有编号或清晰场景命名，并在该目录 README 写明步骤、结果、构建／日期和边界。记录前台是否已完成加载，不存只有过渡效果的页面。优先公开授权样例，附作者、原图链接和许可证；不归档私人相册网格、通知、原图、凭据或个人健康导出。若需要裁剪或遮盖，说明处理范围，不掩盖实际错误。

## 真实 AI 验证

真实调用可能计费，并会发送图片及描述。仅使用已获授权的服务和测试图片；密钥配置放仓库外，禁止直接写入命令参数、源码、报告或日志。不要为自动测试新增一个未经说明的数据上传路径。

当前可选测试位于 `app/src/androidTest/java/app/scalemate/FoodAiIntegrationTest.kt`。它读取目标应用私有 files 目录中的 `ai-validation-private.json`（`baseUrl`、`key`）；涉及私有照片的方法还要求 `ai-validation-photo.jpg`，每个测试方法结束会清理夹具。模型与场景以源码为准；更换模型时检查图片能力。夹具缺失会跳过，不能将跳过记为通过；多个方法需逐个补充夹具、单独执行：

```sh
adb -s <serial> shell am instrument -w \
  -e class 'app.scalemate.FoodAiIntegrationTest#privateFixtureBothFormatsTextAndVision' \
  app.scalemate.test/androidx.test.runner.AndroidJUnitRunner
```

饮食识别 Prompt 每次改动后，必须额外执行下面的基准方法。4 张公开合成样例位于 [food-prompt-baseline](testing/fixtures/food-prompt-baseline/README.md)，构建时只进入测试 APK，不进入业务包。方法逐张检查中英文输出、成品菜分组、原材料拆项、本人摄入合同和图片下标；实际模型、首次失败、重试与未验证边界写入当轮 `docs/testing/` 记录。

```sh
adb -s emulator-5556 shell am instrument -w \
  -e class 'app.scalemate.FoodAiIntegrationTest#privateFixturePromptBaselineChineseAndEnglish' \
  app.scalemate.test/androidx.test.runner.AndroidJUnitRunner
```

这组样例是结构／分组／语言回归，不是营养准确率基准，也不能证明所有模型都遵守 Prompt。没有真实服务授权、私有配置或费用条件时，必须如实记录未执行，不能用固定响应测试冒充真实 AI 通过。

私有文件的传入使用本机受保护文件和 `run-as` 等机制，不在指南中保存真实配置。异常中断后人工检查并清理残留，不依赖 finally 必然执行。测试类实际方法可在源码查询。

推荐场景：两种 API 格式；中英文输出与应用／系统语言优先级；单独吃、多人均分、个人那份的部分摄入、没吃蘸料；多图同餐与重复角度；超时、失败、非法 JSON／旧合同拒绝。固定响应回归应确保 AI 返回 360 kcal 时不会再次除以人数。

报告区分“协议和保存正确”“模型理解符合样例”“营养是否准确”。模型首次失败、重试成功都如实记录，不用重试抹去首次失败。不承诺所有模型始终服从 Prompt。

## 收尾与证据

1. 检查本轮改动、必要测试与截图；记录未验证项和原因，不把测试端点连接成功当成图像识别通过。
2. 清理自己新增的公开图片夹具、测试服务副本和测试餐食，保留用户原来的草稿、服务和默认选项。清理 Health Connect 数据只针对本轮创建且已授权删除的记录。
3. 恢复临时屏幕设置，清理本轮临时测试 APK／夹具与可丢弃仪器测试包；复用既有测试包名，不每轮添加新的桌面 App。正式版与预览版覆盖同一包；调试测试版可能有用户数据，未经确认不卸载。检查暂存区没有密钥、数据库、APK、原始健康 JSON 或私人图片。`.gitignore` 只能辅助，不能替代 diff 审查。
4. `git diff --check`，按需 commit／push；最终说明改了什么、做了哪些验证、还有什么限制。
