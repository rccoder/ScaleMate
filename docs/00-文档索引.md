# 项目文档索引

> 当前行为以 `app/` 代码为准。PRD 记录已确认需求及明确标注的规划；历史版本说明与验收结论只适用于对应版本，不作为恢复旧逻辑的指令。

## 开始工作

1. 阅读根目录 [AGENTS.md](../AGENTS.md)，确认产品边界和用户最新要求。
2. 按任务阅读 [开发指南](01-开发指南.md)、[测试与验收指南](02-测试与验收指南.md) 或 [发布指南](03-发布指南.md)。操作手机前读 [安装与测试环境约定](04-Android%20包安装与测试环境约定.md)。
3. 核对相关源码与最近的 `docs/testing/` 验收，确定本轮验证范围。

产品版本只有正式版、公开预览版和开发调试用的测试版三种；具体包名、签名和数据边界见安装约定。临时仪器测试工具不是另一种产品版本。

## 命名与阅读顺序

持续维护的文档按用途编号，不在文件名加日期；修订时保持名称和编号稳定。编号用于导航，不表示功能实现状态，也不代表需求发生先后。

| 范围 | 用途与命名 |
| --- | --- |
| `00` | 固定文档索引 |
| `01`–`05` | 开发、测试、发布、安装约定与当前实现入口，按工作阅读顺序排列 |
| `10`–`13` | 当前维护的功能规划与 PRD；是否已实现见下方状态表 |
| `20` | 项目演进，按实际事件与版本梳理发展脉络 |
| `testing/YYYY-MM-DD-NN-主题.md` | 一次验收、审查或阶段总结；日期为实际事件／总结日期，`NN` 为当天记录序号 |
| `history/YYYY-MM-DD-主题.md` | 历史需求快照，日期标识对应历史阶段 |

新增指南和 PRD 在相应类别分配空闲编号，不为插入新文档重排已有编号。`testing/` 中持续维护的操作指南也只用编号，不带日期，例如 [实机图片选择操作](testing/01-Android%20实机图片选择操作.md)。

日期不是文档有效期，也不直接取 Git 首次入库日期；跨日验收在正文写明实际范围，无法核实的时间明确说明。发展先后查看 [项目演进](20-项目演进.md)，具体修订查看 Git 历史。根 README／AGENTS、目录 README、Brand 和图集入口保留约定名称；`docs/releases/v*.md` 继续按发布脚本要求使用版本号命名。
