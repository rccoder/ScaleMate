# 称伴 AI 功能原型与设计记录

> 日期：2026-10-17。基于当前 `app/` 模块、称伴 0.1.1 和两份 AI PRD 的可点击原型。截图全部来自手机实机运行，画面中的饮食、睡眠和心率均为合成示例。

[打开截图总览](index.html) · [原型运行与边界](../../docs/testing/AI%20功能交互原型.md) · [食物 PRD](../../docs/称伴食物%20AI%20记录产品需求文档.md) · [健康 PRD](../../docs/称伴健康%20AI%20分析产品需求文档.md)

## 原型位置

- 实现：`app/src/prototype/java/app/scalemate/prototype/PrototypeActivity.kt`。
- 原型 Manifest：`app/src/prototype/AndroidManifest.xml`。
- 构建：在项目根目录执行 `:app:assemblePrototype`，环境详见运行说明。
- 安装包：`app/build/outputs/apk/prototype/app-prototype.apk`，手机安装名称“称伴 AI 原型”。
- 包名 `app.scalemate.prototype`，与正式称伴同时安装；原型入口只进入 Mock 页面。

原型延续称伴的绿色 Material 3 界面，增加饮食和健康页。基础操作仅改变内存状态；相机、AI、同步、导出和分享都以示例流程展示，不访问真实健康信息、不保存 Key、不执行后台任务。正式版 debug／release 不包含这套原型页面。

## 复现截图

先安装并打开原型，在电脑执行：

```sh
python3 design/ai-prototype/capture.py --serial YOUR_DEVICE_SERIAL
```

脚本仅操作 `app.scalemate.prototype`，截图前检查前台包名；会重启原型并走过示例流程，请避免同时操作手机。设备地址不写入脚本。可以通过 `--adb` 指定 adb 路径。

## 本轮验证

- `:app:assemblePrototype` 与 `:app:assembleDebug` 构建通过。
- 检查原型合并 Manifest：不存在蓝牙／健康写入权限，只有原型启动 Activity。
- 实机走查拍照补充、份量确认、编辑／保存、常吃／历史复用、健康对话、导出、多服务配置及提醒预览。
- 原型行为用于讨论页面和操作顺序，不替代 PRD 的正式业务验收。日期、图表和返回文案均为预置，修改字段不会触发真实计算或推理。
