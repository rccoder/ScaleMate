# Android 实机图片选择操作

> 小米 24031PN0DC 上的系统 Photo Picker 操作记录。2026-10-17 验证。用于称伴饮食多图测试，后续测试选图前先看本页；其他系统以当前 UI 为准，不照搬坐标。

## 选择多张图片

1. 在称伴“这一餐”或照片添加页点“从相册选择”。先确认前台是系统图片选择器。
2. **点图片本身会打开大图预览；多选要点图片角上的勾选框。** 本机勾选框位于缩略图右下角，UI 树中资源名为 `com.android.photopicker:id/checkbox`。
3. 按当前 UI 定位每张目标图片内的勾选框，点击后重新检查勾选状态和“已选择 N 项”。不能只按点击次数推断已选中。
4. 点“确认”，等导入完成，回称伴检查缩略图数量。称伴每批上限 6 张；已有图片时，新选择会追加，超限会提示。
5. 拍照可以反复追加；移除缩略图后再次检查当前批次数量。

## 自动化容易踩的坑

- 操作前先唤醒屏幕并确认锁屏状态；UI 树可能包含锁屏后的旧应用内容，不能仅凭它判断可以点击。安全锁屏时请用户解锁，不反复点旧坐标。

- 打开大图预览后，UI 树可能同时包含**预览图片和底下的旧网格**，甚至有相同的图片描述。找到日期描述不代表节点当前可以点击。
- 出现预览时，先返回网格；定位目标图片中可点击的 checkbox，不盲点缩略图中心，不对旧 UI 树连续点击多个图片中心。
- 每次进入、退出系统选择器都重新读取 UI。点击确认后必须验证前台已回到称伴，否则可能是选中数量为 0、确认未生效。
- 按当前资源文件的文案定位控件，例如本轮分析按钮是“开始分析照片”；不要凭记忆猜“开始分析”。
- 选择器不归称伴控制，不为自动化方便修改产品逻辑或加入假选择结果。

## 样例与时间排序

优先用明确知道来源的食物图片。用户已允许本轮使用手机最近的食物照片；选图前仍须确认图片内容符合本次测试，不误选其他照片。项目截图优先用公开授权样例，归档应用内部界面，不归档私人相册网格。

`adb push` 可能保留源文件的旧修改时间，扫描后图片不一定排在相册最前面。不能把“最近上传”等同于“最近拍摄”。

使用公开夹具时：

1. 将原图复制成当前时间的新临时文件，上传到 `Pictures/` 的专用样例名。
2. 触发媒体扫描，按**自己上传的确切文件名**查询 MediaStore 的 `_id`、`datetaken` 和 `date_modified`，只查自己的夹具。
3. 根据查到的时间与当前 UI 识别目标。该选择器的秒数可能没有前导零，例如 `22:53:3`；自动化应解析时间数字，不硬匹配 `22:53:03`。
4. 等待扫描刷新，必要时重新进入选择器。不要通过遍历私人相册找样例，不反复猜坐标。
5. 若需要排查导入的是不是公开夹具，可在本地比较导入图片与夹具的缩小像素差异；不把图片或数据库放入 Git。

## 本轮已验证

- 同一次系统选择中勾选两张公开样例，确认后成功追加到已有批次，缩略图从 1 张变为 3 张。
- 在称伴移除一张，保留两张继续分析。
- 两张样例是同一盘米饭鸡蛋的重复图片，用于检查多图输入和重复角度处理；不能据此宣称各种真实重复角度均能准确去重。
