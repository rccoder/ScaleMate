## 更新检查

原实现每次串行验证最多 20 个历史版本，每个下载清单和签名。此次发现时公开预览通道有 18 个带签名清单的版本，对应约 37 个逻辑请求；正式通道约 13 个。

当前实现：

- 正式通道使用 GitHub `/releases/latest`；预览通道读取版本列表，每个通道只验证最近的必要候选，成功后停止历史探测。
- 已安装最新 Tag 时直接结束；其他情况按签名中的全局版本码选择高于已安装版本的候选。可以从旧版直接下载最新版完整 APK，跳过中间版本。
- 清单和签名并行获取，最多两个请求同时进行。保存最近八个清单及签名，复用前重新验签；检查后点击下载不再重新联网获取同一份清单。
- 候选损坏时最多向同通道三个候选有限回退。缓存被篡改、错 Tag、错误签名仍拒绝；新版验证失败且没有更高有效候选时保留检查失败状态，不因旧版本有效而误报已是最新版。
- 元数据连接／读取超时收紧为 4／6 秒，APK 传输单独处理。手选文件线路仍不悄悄回退，API 发现使用可用的独立线路。
- 正常首次正式检查三个逻辑请求；预览通道需要同时核对正式与预览候选时最多五个；当前已是最新或有缓存时通常只需一次发现请求。重试和 HTTP 重定向另计。

## 更新页交互

每个阶段仅一个醒目的主操作，顺序为：检查更新 → 下载更新 → 安装更新。

- 缩小当前版本信息块；目标版本和操作按钮先展示，不被长更新说明挤出首屏。
- 发现新版后，“重新检查”降为次要文字操作；说明默认显示短摘要，完整内容可展开。
- 下载、校验和打开系统确认期间禁用主按钮；下载失败提供“重试下载”，检查失败提供“重新检查更新”。
- 手动下载和自动下载都只下载与校验，完成后由用户点击“安装更新”才进入 Android 确认。等待安装时不再提供会重置进度的检查按钮。
- 保留下载取消与重试、安装权限及系统取消后的再次安装入口。
