# AI 食物分析流式进度提示

- 日期：2026-10-31（Asia/Shanghai）
- 包名：`app.scalemate.fooddev`
- 性质：食物图片分析等待期间显示首 Token 延迟与持续递增的 Token 进度
- 证据目录：[ai-stream-progress-evidence](2026-10-31-08-ai-stream-progress-evidence/)

## 用户要求

AI 分析食物经常需要等待几十秒。用户希望提示不仅说明正在分析，还要显示 AI 是否已经开始返回、首 Token 是否及时，以及当前大约收到了多少 Token，用来缓解等待焦虑。这里不需要精确 Token 数，允许粗略估算。

## 实现

- 食物识别请求改为读取 SSE 流，首个正文片段到达后立即把状态切换到“AI 已开始返回”。
- 处理中显示“首 Token 已在 X 秒内返回，当前约 N 个输出 Token（粗略估算）”。估算在每个正文片段到达时更新，不等待完整 JSON。
- 估算采用轻量混合文本启发式：ASCII 约 `0.28`、空白约 `0.1`、中文及其他非 ASCII 字符约 `1`，最后向上取整。它不是供应商分词器，只用于进度反馈。
- OpenAI 请求启用 `stream_options.include_usage`。如果兼容服务明确拒绝该可选参数，会去掉它自动重试一次，仍保留 SSE 正文进度。
- OpenAI 在结束事件后的 usage、Anthropic 在 `message_start`／`message_delta` 中的 usage 都会合并；分析完成后的结果卡仍只显示服务实际返回的输入、输出和总 Token 数。
- Anthropic 可能先发 usage、后发正文。界面只有在收到正文片段后才切换到接收状态，避免短暂显示“0 片段”。

## 边界

- 截图来自本地 Mock 和模拟器，不代表真实供应商的延迟、Token 计费或服务兼容性。
- 估算不是分词器结果，不能用于计费、额度判断或准确率统计；完成后的服务 usage 才是实际值。
- 本轮没有修改食物识别 Prompt，因此没有触发 4 张真实 AI Prompt 基准回归，也没有调用真实模型。
